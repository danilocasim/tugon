# Tugon MVP — implementation checklist

Build the production pilot of the existing resident, barangay staff/administration, and tanod portals. **`prototype/` is the design and workflow reference, not a production service.** Preserve its screens and responsive behavior; replace its demo data, permissions, authentication, and integrations. The plan assumes one barangay for the pilot, not a multi-tenant product.

- [Architecture](./ARCHITECTURE.md): app boundaries, data, auth, and integrations.
- [Design parity](./DESIGN-PARITY.md): every screen family, including mobile and print acceptance.
- [Operations](./OPERATIONS.md): Coolify topology, secrets, backups, release gates, and manager approvals.

**How to use:** Work in dependency order. Check a slice off only after recording the command or scenario, environment, result, and screenshot/print evidence where applicable. Each slice includes its own migration, policy, interface, and tests when relevant. Product work, infrastructure changes, provider sends, and releases are not authorized by this document.

## Local and CI commands

Run Supabase commands from the repository root with CLI `2.113.0` against a disposable stack. Run browser checks with `node ops/with-local-supabase.mjs npm --prefix apps/web run test:e2e`, which injects local-only connection details without writing secrets to disk.

Start the linked local preview with `node ops/with-local-supabase.mjs npm --prefix apps/web run dev` after starting the isolated stack. The entry page is at `http://localhost:3100/`; use `/resident`, `/barangay` and `/tanod` for the three portals. Use `TUGON_TEST_ORIGIN=http://localhost:3100` when the preview is already running.

| Command | Proves |
| --- | --- |
| `npm --prefix apps/web ci` | Reproducible install from product lockfile |
| `supabase start` then `supabase migration up --local` | SQL can run on a fresh local development stack |
| `supabase test db` | Migrations, policies, transaction invariants and negative access tests |
| `npm --prefix apps/web run lint` | App and test lint rules |
| `npm --prefix apps/web run typecheck` | Next route type generation and TypeScript contracts |
| `npm --prefix apps/web run test` | Domain, formatting, provider, and integration fixtures |
| `npm --prefix apps/web run build` | Production output, fonts, maps, and route build |
| `npm --prefix apps/web run test:e2e` | Browser scenarios, viewport parity and print check fixtures |

After 1.2, the reader-facing app always uses verified identity and authorized live data; test harnesses can seed only disposable environments. Do not promote the prototype JSON store, default credentials, public demo resets, or mocked delivery to production.
